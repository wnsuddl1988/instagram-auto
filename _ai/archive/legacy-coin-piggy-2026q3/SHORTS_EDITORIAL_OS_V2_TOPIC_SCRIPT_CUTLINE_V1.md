## 0. 이 문서가 필요한 이유

기존 `lib/finance-editorial-topic-bank.ts`는 12 subtopic × 9 lane 조합으로 500개 제목을 기계 생성한 구조다. 산출물은 사실로서 틀리지 않지만 **시점이 없고 고유명사가 없어** 시청자가 "지금 이걸 볼 이유"를 찾지 못한다. Owner 판정: `누구나 아는 상식 전달 / 그저그런 대본`.

본 문서는 그 실패를 반복하지 않기 위해, **프로그램이 기계적으로 집행할 수 있는 형태**로 합격선을 고정한다.

### 1.2 웹 리서치 (금융 숏폼 훅 일반론)

- 금융 시청자는 **약 1.5초** 안에 "광고 냄새"가 나면 이탈한다. 훅은 결과가 아니라 **구체적 수치 / 검증 가능한 근거 / 명명된 실수**로 시작해야 한다. ([CreatorHouse 2026](https://creatorhouse.app/blog/instagram-reel-hooks-money-finance-2026))
- 훅 길이 **8~15 단어**, 첫 **3초** 이내 착지. 3초 시점 잔존 60%+ 가 알고리즘 노출의 분기점. ([Kineclip 2026](https://kineclip.com/blog/how-to-write-viral-hooks-short-form-2026/))
- 금융에서 실패하는 훅: 수익 보장·암시, "항상 통한다"류, 일확천금 프레이밍, 구체성 없는 일반론, 교육으로 위장한 홍보.
- 반복 검증된 훅 유형: Contrarian Claim / Mistake Warning / List Tease / Curiosity Gap / Direct Callout / Story Cold-Open.

> 주의: 1.2의 수치(1.5초, 60%, 50% hook-rate 등)는 **외부 콘텐츠 마케팅 자료 출처**이며 본 프로젝트에서 독립 검증하지 않았다. 설계 지침으로 사용하되, 성과 보장 근거로 인용하지 않는다.

## 2. 파이프라인 위치

```
[L1] 실시간 수집   ECOS · FRED · 네이버(뉴스/데이터랩)
        ↓ 실물 데이터
[L2] 프롬프트 조립  수집값을 슬롯에 주입해 LLM 프롬프트를 매회 새로 생성
        ↓ Owner가 복사 → LLM 실행 → 결과 회수 (비용·품질 통제 지점)
[L3] 커트라인 검사  ← 본 문서가 정의하는 대상
        ↓ 통과분만
[L4] 스토리보드 / Veo 프롬프트 / 렌더
```

L3는 **생성하지 않는다. 판정만 한다.** 기준을 발명하는 주체는 본 문서(=Owner 승인)이고, 프로그램은 집행자다.

| ID | 항목 | 판정 방법 | 탈락 사유 |
| --- | --- | --- | --- |
| `HC-01` | 시점 표현 없음 | 제목에 날짜/`오늘`/`어제`/`이번 주`/`9월` 등 시점 토큰 부재 | 지금 볼 이유가 없음 |

| `HC-03` | 훅 길이 초과 | 첫 자막(훅) 공백 기준 15단어 초과 또는 40자 초과 | 3초 내 착지 불가 |

### 3.1 금칙어 목록 (초안)

**보장·단정형**: 무조건, 확실히, 반드시 오른다, 100%, 보장, 절대, 필승, 대박
**수익 암시형**: 떡상, 존버하면, 지금 사면, 얼마 번다, 수익 인증
**과장 위험형**: 망한다, 폭망, 거지 된다 (※ `경고` lane에서도 사용 금지 — 공포 마케팅 회피)

> `역대급`은 벤치마킹 채널이 상시 사용하나, **사실 근거가 있는 경우만** 허용한다(예: "잔액 역대 최대"가 통계로 확인될 때). 근거 없이 쓰면 `HC-06` 위반.

### 3.2 근거 신선도 창 (`HC-05` 상세)

근거를 하나의 7일 기준으로 판정하면 **통계 근거가 거의 항상 탈락**한다. ECOS·KOSIS 등 공식 통계는 월간·분기 단위로 발표되므로 발표 직후를 제외하면 7일을 넘는다. 근거 종류별로 창을 분리한다.

| 근거 종류 | `evidenceKind` | 신선도 창 | 판정 방식 |
| --- | --- | --- | --- |
| 뉴스·보도자료 | `news` | **7일** | `publishedAt`이 기준일 −7일 이내 |
| 공식 통계 (ECOS/KOSIS/한은/금융위 등) | `statistic` | **해당 지표의 최신 발표분이면 통과** | 더 새로운 발표분이 존재하지 않으면 `fresh`. 상한 안전장치로 **400일** 초과 시 `stale` |
| 제도·정책 문서 (시행령, 약관, 공시) | `policy` | **180일** | 시행일 기준. 시행 예정 문서는 `eventDate`로 판정 |
| 배경 지식 (개념 설명, 용어) | `background` | **창 없음** | 신선도 판정 대상 아님. 단독으로는 `HC-05` 충족 불가 |

**`HC-05` 최종 판정 규칙:**

1. 각 근거를 `evidenceKind`에 따라 `fresh` / `stale`로 분류한다.
2. `background`는 신선도 계산에서 제외한다.
3. **`fresh`인 근거가 1개 이상 있으면 통과.** 전부 `stale`이면 탈락.
4. `news` 종류 근거가 **0개**이면서 `statistic`만으로 구성된 후보는 **`S-05`(시의성) 최대 1점**으로 제한한다 — 통계만으로는 "지금 볼 이유"가 약하기 때문.

> `statistic`을 "최신 발표분이면 통과"로 둔 이유: 기준금리가 3개월째 동결이라도 **그것이 현재 사실**이다. 오래되었다는 이유로 탈락시키면 사실을 말할 수 없게 된다. 대신 §4 `S-05`에서 점수를 낮춰 순위로 불이익을 준다.

> **`statistic`의 "최신 발표분" 판정은 API가 최신 기간을 실제로 조회해 확인한다.** 사람이 눈으로 판단하지 않는다. 최신 기간 조회에 실패하면 `unknown`으로 두고 `fresh`로 간주하지 않는다.

| `S-02` | 큐리오시티 갭 | 답이 제목에 다 있음 | 약한 궁금증 | 답을 봐야만 알 수 있음 |

| `S-10` | 채널 톤 적합 | 이질적 | 무난 | 탐정 캐릭터 포맷에 자연스러움 |

### 4.1 훅 유형 (S-02/S-04 채점 참고)

허용 유형 — 벤치마킹 관찰 + 웹 리서치 교집합:

1. **진짜 이유형** — `~한 진짜 이유` (관찰 10건 중 4건)
2. **정보 격차형** — `~ 알고 있었어?` / `~ 모르고 지나치면`
3. **명명된 실수형** — 특정 행동을 실수로 지목 (결과 약속 아님)
4. **통념 반박형** — `~라고 알고 있지만 아니다`
5. **직접 지목형** — `~한 사람이라면`

금지 유형: 수익 약속형, 공포 조장형, 낚시 후 무관한 내용.

## 5. 대본 구조 기준

8-Scene 기준. 각 장면은 `한 클립 = 한 동작` 원칙(Veo 제약)을 지킨다.

| Scene | 역할 | 필수 조건 |
| --- | --- | --- |
| 1 | 훅 | `HC-03` 충족. 질문형 또는 정보 격차형 |
| 2 | 손실 회피 | `모르고 지나치면` 계열. 아직 답 주지 않음 |
| 3 | 근거 제시 | **뉴스 헤드라인/통계 카드 시각 노출**. 출처·날짜 포함 |
| 4 | 배경 설명 | 왜 이런 일이 생겼는지 |
| 5 | 핵심 반전 | 통념과 실제의 차이. 수치는 overlay 합성(`HC-10`) |
| 6 | 영향 | 시청자에게 무엇을 의미하는지 |
| 7 | 실행 | **오늘 1분 내 가능한 행동 1개** (`S-07`) |
| 8 | 마무리 + 고지 | 투자 책임 고지 노출(`HC-09`) |

- 총 길이 목표: **20~45초**. 20초 초과 시 장면당 정보 밀도 유지 필요.
- 내레이션은 장면당 1~2문장, 구어체.
- 숫자는 반드시 §3 `HC-08`에 따라 근거 문서와 대조.

## 6. 근거(Evidence) 레코드 요구사항

모든 후보는 아래 필드를 갖춰야 L3 검사 대상이 된다.

```
evidence: [
  {
    claim:        "본문에서 이 근거가 뒷받침하는 문장",
    evidenceKind: "news | statistic | policy | background",   // §3.2 신선도 창 결정
    sourceName:   "발행 매체/기관",
    sourceUrl:    "https://...",
    publishedAt:  "2026-09-14",
    eventDate:    "2026-09-14",        // policy: 시행일. 없으면 publishedAt과 동일
    figure:       "6조 8,321억 원",     // optional
    figureAsOf:   "2026-07 기준",       // figure 있으면 필수
    isLatestRelease: true,             // statistic 필수. API 최신기간 조회로 확인
    accessLevel:  "OBSERVED_FULL | OBSERVED_PARTIAL | INDEX_ONLY"
  }
]
```

- `accessLevel: INDEX_ONLY`(검색 요약·API 스니펫만 본 상태)인 근거는 **수치 인용 불가**. 맥락 참고로만 허용.
- **네이버 뉴스 API 결과는 기본 `INDEX_ONLY`다.** 제목·요약·링크·발행일만 제공되고 본문 전문이 없기 때문. 따라서 **뉴스에서 읽은 수치를 그대로 영상에 쓸 수 없다.**
  - 수치가 필요하면 (a) 통계 API(`statistic`)에서 직접 가져오거나, (b) Owner가 원문 기사를 열어 확인하고 `OBSERVED_FULL`로 승격해야 한다.
  - 이 규칙이 `HC-08`(숫자 출처 불일치)과 함께 허위 수치를 막는 2중 장치다.
- 동일 수치가 2개 이상 출처에서 확인되면 `S-01` 가점 판단에 유리하나, 별도 점수 항목으로 두지 않는다.

### 6.1 출처 신뢰 등급

장기 운영(100~1,000편) 시 출처 품질이 채널 신뢰도를 좌우한다. 등급별로 허용 범위를 다르게 둔다.

| 등급 | 해당 출처 | 허용 범위 |
| --- | --- | --- |
| `T1` 공식 1차 | 한국은행(ECOS), 통계청(KOSIS), 금융위·금감원, 기재부, 예금보험공사, DART, 한국거래소 | 수치 인용 가능. 단독 근거로 충분 |
| `T2` 공인 매체 | 연합뉴스, 주요 경제지·일간지, 공신력 있는 협회 발표 | 사실 인용 가능. 수치는 `OBSERVED_FULL`일 때만 |
| `T3` 일반 | 기타 언론, 블로그, 커뮤니티 | **근거로 사용 금지.** 주제 발굴 힌트로만 |

- `T3`는 evidence pack에 넣지 않는다. "이런 게 화제구나"를 아는 용도로만 쓰고, 실제 근거는 `T1`/`T2`에서 다시 찾는다.
- 수치를 화면에 띄우는 장면(§5 Scene 3·5)은 **`T1` 근거를 우선**한다.

## 7. 프로그램 구현 시 주의

- L3는 **탈락 사유를 반드시 구조화해 반환**한다(`{passed: false, violations: ["HC-02", "HC-05"]}`). 재생성 프롬프트에 그대로 주입하기 위함.
- 하드 컷은 정규식·토큰 매칭 수준으로 결정론적이어야 한다. LLM 재호출로 판정하지 않는다(비용·재현성).
- `S-02`, `S-03`, `S-08`, `S-10`은 결정론적 판정이 어렵다. **V1에서는 Owner 수동 채점**으로 두고, 충분한 샘플이 쌓인 뒤 자동화를 재검토한다.
- 금칙어 목록은 코드 상수가 아니라 **설정 파일**로 분리해 Owner가 직접 수정 가능하게 한다.

## 8. V1 한계 (명시)

- 본 기준은 벤치마킹 **1개 채널 / 그리드 10건 / 릴스 1편 내부**만 관찰해 도출했다. 표본이 작다.
- 조회수는 썸네일 표기값이며 기간·유입 경로를 알 수 없어 인과 근거로 쓸 수 없다.
- §1.2 외부 수치는 미검증 마케팅 자료다.
- 따라서 이 커트라인은 **가설**이며, 실제 게시 성과로 교정해야 한다. 교정 전까지 "이 기준을 통과하면 잘 된다"고 말하지 않는다.
