Google Flow에서 "생성 시작" 클릭 → 10초 이내 "N 크레딧 사용 승인" 대화상자 → 승인 클릭 → 1~2분 내 영상 생성 완료. 사용자가 화면을 직접 보며 확인한 실측 타이밍(2026-09-17).

`run-owl-flow-motion-execute-once-v1.mjs`의 완료 감지 로직에 두 가지 버그가 있었고 모두 수정함:
1. 승인 대화상자를 전송 직후 1회만 체크해서 렌더링 지연 시 놓침 → 15초간 짧은 간격 재시도 + 이후 폴링 루프에서도 계속 재확인하도록 수정.
2. 완료된 영상이 캔버스 목록 뷰의 `flow-video-tile` 카드로 남아있다고 가정했으나, 실제로는 완료 시 곧바로 상세 플레이어 화면(video 태그 + 다운로드 버튼)으로 전환되어 목록에 타일이 아예 안 보이는 경우가 있음(Scene 5, 6 둘 다 재현) → 매 폴링 사이클마다 "이미 상세 화면으로 전환됐는지"를 먼저 확인하도록 수정.

**Why:** 이 두 버그로 Scene 5, 6 모두 자동화가 완료를 인식 못 해 사용자가 화면을 직접 보고 알려줘야 했음("flow에서는 완료를 너무 인식 못하는거 같아").

**How to apply:** 앞으로 Flow 관련 스크립트를 수정하거나 디버깅할 때, 완료 판정은 (a) 목록 뷰 타일의 % 텍스트 소멸, (b) 상세 화면 직행 두 경로를 모두 확인해야 함. 폴링 간격 5초, 최대 대기 10분이면 1~2분 완성 타이밍에 충분히 여유 있음. [[feedback_flow_always_lite_model]] 참고 — 모델은 항상 lite 고정.

추가 버그 3건(2026-09-17, Scene 7/8에서 발견):
- 승인 대화상자가 닫히는 전환 애니메이션 중 `video`/다운로드 버튼이 DOM에 잠깐 나타났다 사라지는 잔여 렌더링 때문에, 승인 직후 5~6초 만에 "이미 상세 화면"으로 오판되어 완료로 착각하고 실패 처리되는 사고가 반복됨(`isVisible()` 체크로도 못 걸러짐) → 승인 시각(`approvedAt`)을 기록해 승인 후 최소 15초는 상세 화면 감지 자체를 건너뛰도록 수정.
- 다운로드 경로가 "더보기(⋮) → 미디어 다운로드 → 원본 크기" 3단계라고 가정했으나 실제 UI에는 "더보기" 버튼이 없고 상세 화면 상단에 다운로드 아이콘이 바로 노출됨 → 다운로드 아이콘 직접 클릭으로 수정(Scene 5/6에서 사람이 수동으로 확인한 실제 클릭 경로와 일치).
- 두 버그 모두 `run-owl-flow-motion-execute-once-v1.mjs`에 반영 완료.
