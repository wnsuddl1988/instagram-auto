부엉박사/금박사 영상(모션) 생성 프롬프트 작성 시 고정 규칙.

## 0. 최우선 — 프롬프트 강화로 텍스트 깨짐을 막으려 하지 말 것 (2026-09-21 확정)

**Veo 텍스트 깨짐·소품 이탈은 프롬프트로 막을 수 없다는 것이 87씬 전수조사로
확정됐다.** 실행 규칙은 `_ai/CURRENT_STANDARDS.md` §0 "★ 영상 생성 절대규칙"에
등록돼 있으니 영상 프롬프트를 쓰기 전 반드시 그것부터 읽는다. 요지:
- 텍스트 깨짐은 **0.1초 시작 프레임에 이미 확정**돼 있다(프롬프트 개입 구간 없음).
  큰 글자는 87씬 실패 0건, 작은 소자만 깨진다 → **이미지 설계 단계에서** 작은
  보조 텍스트를 빼는 것이 유일한 해법.
- 소품 이탈은 **그립 × 팔 동작** 조합 문제 → 이미지에서 감싸쥠/바닥거치로 그리고,
  프롬프트에서는 동작을 '빈 손'에만 배정한다.
- 상세 근거는 [[project_veo_text_heavy_background_root_cause]].

**주의 — `_ai/owl-ep10-video-generation-prompts.md`는 검증된 성공 사례가 아니다.**
그 문서는 8·9·10번 실패를 확인한 **뒤에 사후 작성된 "다음 시도용"** 문서이며
(파일 타임스탬프 09:38 > 영상 생성 08:45~09:20), 실전 검증된 적이 없다. 실제로
그 강화안대로 재시도한 결과도 전부 실패했다(`_ai/HANDOFF_SESSION_TEMP_ACCOUNT.md`
§12: "FROZEN PROP TREATMENT, pixel-perfect identical 같은 지시는 실효성이 거의
없다 — 프롬프트를 더 강하게 쓰는 시도는 그만하는 게 낫다"). 이 문서를 "성공
프롬프트"로 인용하지 말 것.

## 0-0. 2026-10-01 Owner 지시로 "끝 글자 소실·입 멈춤"은 프롬프트 강화 + 구조 변경을 시험한다 (위 0번과 구분)

위 0번은 **시작 프레임에 확정되는 글자 깨짐**(작은 글씨)에 대한 결론이다. 황소 12편에서는 다른 현상이 나왔다 — ① **8초 클립 끝 0.5~1초에 보드 글자가 fade로 사라짐**(s14: 7.3s 흐려짐→7.9s 빈 보드) ② **16개 중 15개가 대사 뒤 0.55~1.16초 입이 더 움직임**. Owner가 "프롬프트 강화해서 다시 줘 / 다음부턴 더 잘 적용되게 강화해"라고 지시 → 생성기 `build-video-generation-prompts.mjs`를 ⓐ **소품 씬 항상 10초**(구조적 해법: 사라지는 구간을 사용 구간 밖으로) ⓑ 글자 보존에 "끝 프레임까지 선명·fade/dissolve 금지" ⓒ SPEECH TIMING 2단계(듣는 구간 입 완전히 닫음·음성 없음) + FINAL REMINDER로 강화. **첫 측정(12편 s14 재생성, n=1): 10초 티어는 효과 있음(끝 글자 선명), 입 멈춤 문구 강화는 효과 없음(Veo 음성 끝 +1.27초, 구본 +1.39초, 6.9~7.7초에 입 열림) → 다음 편은 `--pilot-dialogue` A/B 시험.** (아래는 처음 계획) 효과는 미확정 — 다음 편 검수에서 12편 기준선(15/16 경고, 평균 초과 약 0.9초)과 비교하고 CURRENT_STANDARDS §A-5에 기록한다. 프롬프트만으로는 안 먹힐 수 있으니(위 0번 경험) 10초 티어 구조 변경이 주 해법, 문구 강화는 보조다.

## 0-1. 새 프롬프트 작성 시 기존 기록 확인 (여전히 유효)

새 편 프롬프트를 쓰기 전 `_ai/` 안의 관련 기록(CURRENT_STANDARDS.md 절대규칙,
HANDOFF 문서의 실패 로그)을 먼저 읽는다. 기억이나 자체 판단으로 새로 쓰지 않는다.

**Why:** 2026-09-21 금박사 6편에서 10개 씬 영상 프롬프트를 새로 작성하면서 기존
성공 사례와 대조하지 않고 "5요소 포함"이라는 형식만 맞춰 썼다가, 10개 중 5개
(s2·s6·s7·s9·s10)가 재생성 대상이 되는 사고가 났다. Owner가 "정말 정확하게
확인한 거라면 메모리로 남겨라", "10개 중 5개가 오류라는 게 별거 아닌 것 같냐"고
강하게 질책함. 원인 조사 결과: 소품/손을 "A 지점을 가리키다 B 지점으로 이동"
시키는 MOTION DETAIL 문구("point to box 1, then box 2", "gesture ... along the
chart/timeline", "raise phone, settle, raise again")를 쓴 씬만 골라서
실패했다 — 캐릭터가 프레임 밖으로 튀어나가거나(모션 블러+점프), 소품이 손에서
빠져나가 허공에 뜨거나, 이동 경로에 걸친 배경 텍스트·숫자가 재해석되어 깨졌다.
반면 CTA의 "제자리에서 흔들기"(같은 자리에서 반복, 이동 없음)와 10편의
"holds/points steadily at"(한 지점 고정)는 문제없이 성공했다 — 이 차이는 대조
없이는 발견하지 못했다.

**How to apply:** 새 편의 씬별 영상 프롬프트를 쓰기 전, 이미 존재하는 성공
프롬프트 문서를 열어 MOTION DETAIL 문장을 그대로 베끼듯 재사용한다. 특히
"holds/points steadily at one fixed spot", "does not travel/sweep/trace"처럼
한 지점 고정 표현을 기본값으로 쓰고, 그 문서에 없는 새로운 동작 패턴(지점 간
이동, 반복 왕복)을 임의로 지어내지 않는다. `_ai/CURRENT_STANDARDS.md` §0에도
이 원칙과 사고 사례를 반영해둠 — 두 문서를 같이 갱신 상태로 유지할 것.

## 1. 텍스트 보존 지시는 강하고 구체적으로

`_ai/CURRENT_STANDARDS.md` §0의 영상 프롬프트 5요소 중 "④부정 프롬프트(...텍스트
왜곡 금지)"를 "no warped Korean text" 같은 짧은 한 줄로만 넣지 않는다. 배경의
작은 간판·스크린 메뉴까지 포함해 명시적으로 강하게 쓴다:

```
CRITICAL TEXT PRESERVATION: every piece of Korean text visible anywhere in the
frame — including small background signage, screen menus, and wall banners —
must remain pixel-perfect identical to the reference image for the entire
duration. Do not let any character shift, blur, morph, or misspell. If motion
would risk distorting any text, keep that element completely static instead.
```

**Why:** 10편 영상 생성에서 8·9·10번 씬의 배경 소형 텍스트가 심하게 깨져
나왔다(예: "든든한 노후, 함께 만드는 미래" → "문든한 노후, 할께 만드는 이레").
원본 정지 이미지는 확인 결과 전부 정상이었고, Veo 영상 변환 단계에서 발생한
문제였다. 프롬프트의 텍스트 왜곡 금지 문구가 "no warped Korean text" 한 줄뿐이라
실효성이 약했다는 게 결과로 드러났는데도, 처음엔 "문서 요구사항은 명시했다"고
방어하려다 Owner에게 "결론이 내 잘못이 아니라는 거냐"는 강한 질책을 받음
(2026-09-21). CURRENT_STANDARDS.md에 이미 있던 요구사항을 형식적으로만
반영하고 효과를 검증하지 않은 게 문제.

## 2. 씬을 몰아서 생성/검수하지 않는다

영상(또는 이미지) 생성을 여러 씬 한꺼번에 요청받아 처리할 때, 다 만들어질
때까지 기다렸다가 나중에 몰아서 검수하지 않는다. 씬 하나가 나올 때마다 바로
프레임을 뽑아 텍스트 왜곡·캐릭터 일관성을 확인하고, 문제 있으면 그 자리에서
프롬프트를 고쳐 재시도한다.

**Why:** 10편 영상 10개를 한 번에 받아서 검수하다 보니 8·9·10번 문제를
뒤늦게 한꺼번에 발견했다. 씬 단위로 즉시 확인했다면 첫 문제 발견 시점에
프롬프트를 고쳐 나머지 씬에 반영할 수 있었다.

**How to apply:** 다음 편부터 영상 생성 워크플로는 "1개 생성 → 프레임 확인
→ 문제없으면 다음, 있으면 프롬프트 수정 후 그 씬 재시도"를 기본 루프로 한다.
[[feedback_image_background_korean_text_only]](이미지 생성 단계에서 이미
한 번 겪은 비슷한 문제)와 연결 — 텍스트 관련 문제는 이 프로젝트에서 반복되는
리스크 유형이므로 매번 결과로 검증하는 습관이 특히 중요하다.

## 3. CRITICAL TEXT PRESERVATION은 처음부터 전 씬에 동일 적용

10편에서 1~7번 씬은 "no warped Korean text" 약한 문구로 작성했고(운 좋게
핵심 정보는 유지, 배경 디테일만 미세 왜곡), 8~10번만 사고 이후 강화된
`CRITICAL TEXT PRESERVATION` 블록을 추가하는 식으로 뒤늦게 대응했다. 이렇게
편 하나 안에서 씬마다 프롬프트 강도가 다르면 재발 방지가 반쪽짜리가 된다.

**Why:** Owner가 "실수 자체를 안 하는 게 제일 중요한 문제"라고 재차 강조
(2026-09-21) — 사고 이후 일부만 땜질하는 방식은 다음 편에서 처음 씬부터 다시
같은 실수를 낼 위험을 남긴다. 1~9편의 실제 성공 프롬프트 원문은 코드베이스
어디에도 파일로 남아있지 않다는 것도 이번에 확인됨(조립 로그·job 상태 파일만
있고 프롬프트 텍스트 자체는 세션 안에서만 존재하고 사라짐) — 그래서 "예전엔
어떻게 썼길래 괜찮았는지" 사후 비교가 불가능하다.

**How to apply:** 새 편의 씬별 영상 프롬프트를 처음 작성하는 시점부터, 모든
씬에 예외 없이 `CRITICAL TEXT PRESERVATION` 블록(위 예시 문구)을 기본 포함한다.
"이 씬은 배경 텍스트가 적어서 괜찮겠지" 같은 판단으로 일부 씬만 약하게 쓰지
않는다. 그리고 이번 기회에 확정판 프롬프트 원문을 `_ai/owl-epN-video-generation-prompts.md`
같은 파일로 남겨(이번 10편처럼) 다음 편 작성 시 실제 비교 근거로 삼을 수 있게
한다 — 이 파일들을 지우지 말고 편별로 누적 보관하는 것 자체가 재발방지책이다.
