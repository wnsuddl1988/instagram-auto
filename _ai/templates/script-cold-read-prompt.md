# 대본 새 독자 읽기 점검 (cold-read) — CURRENT_STANDARDS 규칙 29

**목적:** 대본을 Owner에게 보이기 전에, 맥락 없는 독자가 전체를 읽고 "무슨 말인지·하나로 이어지는지·어디서 막히는지"를 말하게 해 결함을 먼저 잡는다. **성과 예측기가 아니라 결함 탐지기다.**

## 시험 결과 (2026-10-02, 규칙 29의 근거)
- **훅 3문장만 읽히기 → 폐기.** 13개(과거 편 12 + 반려 초안 1)로 시험했는데 점수가 성과와 무관했고, Owner가 이해 못 하신 증권사 리포트 초안이 가장 높은 점수(4→3)를 받았다.
- **전체 대본 읽히기 → 채택.** 6편(황소 4·5·13·14편 최종본, 부엉 15편, 반려 초안)을 읽혔더니 반려 초안만 "구조가 따로 논다 / '쏠림'이라는 단어로만 억지로 붙었다 / 투자자가 얻을 행동 없다"로 지목했다(Owner 지적과 같은 내용). 나머지 5편은 "하나로 이어짐".
- **만족도 점수(1~5)는 6편 모두 3점이라 쓰지 않는다.** 높은 성과(랠리·실업급여)와 낮은 성과를 구분하지 못했다.
- **한계:** 표본 6편에 반려 사례 1건. 모델 독자는 사람 시청자가 아니다. 소재의 매력·도달은 예측하지 못한다(잘된 편에서도 막힌 곳 목록은 나온다). 구조 결함·앞뒤 불일치·약한 연결·정의 없는 용어를 찾는 용도로만 쓴다.

## 절차 (대본 검사기 통과 후, Owner에게 대본을 보이기 전)
1. 대본 전체(오프닝·마지막 약속 포함)를 파일로 만든다. 제목·소재명·성과 같은 힌트는 넣지 않는다.
   ```
   node scripts/make-cold-read-file-once.mjs --scenes <scenes.json> --out C:/tmp/cold-read/<편>.txt
   node scripts/make-cold-read-file-once.mjs --spec scripts/_<char>-ep<N>-assembly-spec.mjs --out C:/tmp/cold-read/<편>.txt
   ```
2. 서브에이전트(`general-purpose`, 모델 sonnet) **1개**에게 아래 프롬프트를 준다. 그 파일 하나만 읽게 하고 다른 파일·웹 검색은 금지한다. 정보가 거의 없는 독자여야 하므로 대본이 나온 이 대화의 맥락을 넘기지 않는다.
3. 판정은 아래 표대로 한다. 결과(JSON 원문 + 내가 한 조치)를 `_ai/{char}-ep{N}-cold-read.md`에 남기고 보고에 "검증한 것"으로 붙인다.

### 프롬프트 (그대로 사용, 독자 문구만 캐릭터에 맞게)
- 황소특보: `당신은 주식 투자를 하는 한국의 일반 개인투자자`
- 부엉박사: `당신은 경제 지식이 보통 이하인 한국의 일반 시청자`

```text
Read 도구로 아래 파일 하나만 읽으세요. 다른 파일·폴더 검색, 웹 검색은 금지입니다.
파일: <절대경로>

이 파일은 약 2분짜리 인스타그램 릴스 음성 대본 전체입니다(문장 순서대로). 당신은 <독자 문구>이고, 이 영상을 처음부터 끝까지 한 번 들었다고 가정합니다. 영상 제목·썸네일·설명은 못 봤습니다. 솔직하게 답하고, 모르면 "모르겠음"이라고 쓰세요. 추측으로 채우지 마세요.

Q1. 이 영상이 말하려는 핵심을 한 문장으로 쓰세요.
Q2. 영상이 끝난 지금, 내가 가져갈 결론이나 해야 할 일이 있다면 한 문장으로 쓰세요. 없으면 "없음".
Q3. 주제가 하나로 이어지나요, 따로 노는 이야기가 섞였나요? 이어진다면 무엇이 잇는지, 따로 논다면 어디서 갈라지는지 쓰세요.
Q4. 이해가 안 되거나 앞뒤가 맞지 않는 곳을 그대로 인용해 나열하세요(없으면 "없음").
Q5. 끝까지 들은 뒤 "얻은 게 있다"는 만족도를 1~5점(1=시간 낭비, 5=알찼다)으로 쓰세요.

답은 JSON 한 덩어리로만 출력하세요.
{"q1":"","q2":"","q3":"","q4":[],"q5":0}
```
(Q5는 시험 때 쓰던 항목이라 남겨 두되 판정에 쓰지 않는다.)

### 판정 표
| 결과 | 조치 |
|---|---|
| Q3이 "따로 논다 / 억지로 붙었다 / 단어로만 연결" | **반려.** 소재·구조를 다시 정한다(두 소식을 묶었다면 하나로 줄이거나 인과를 찾는다). Owner에게 대본을 보이지 않는다. |
| Q2가 "없음" | **반려.** 시청자가 가져갈 결론·행동을 만들거나 소재를 바꾼다. |
| Q1이 소재를 한 문장으로 못 쓰거나 "모르겠음" | **반려.** |
| Q4 목록 | 항목마다 **수정**하거나 **수정하지 않는 이유**를 기록한다. 수치 불일치·앞뒤 모순·정의 없는 용어는 수정이 기본이다. 채널 소개 부족("황소특보가 뭔지")은 오프닝 문장을 파일에 포함하면 보통 사라진다. |
| Q3 "대체로 이어짐 + 곁가지 지적" | 곁가지 문장을 삭제하거나 앞 구조에 잇는다(예: 11번 문장). |

수정 후 대본이 크게 바뀌었으면(반려 사유였으면) 한 번 더 돌린다. 최대 2회, 그래도 반려면 Owner에게 소재 교체를 제안한다.

## 하지 않는 것
- 점수로 합격/불합격을 가르지 않는다(변별력 없음 확인).
- 이 결과를 "반응이 좋을 것"의 근거로 보고하지 않는다. 보고에는 "결함 탐지 결과"로만 쓴다.
- 서브에이전트에 편집·명령 권한을 요구하지 않는다(읽기 전용 질의 1회).
